# Техническое задание: «Цифровой деканат будущего» (Конкурсный прототип)

## 1. Общая информация и ограничения
- **Цель:** Создать рабочий веб-прототип личного кабинета студента, где расписание, оценки, заявки на справки и уведомления собраны в одном удобном интерфейсе.
- **Адаптивность:** Строгий Mobile-first. Все сценарии обязаны безупречно работать на ширине от `360px` (нижняя навигация Tab Bar на мобильных, боковое меню на десктопе).
- **Дисклеймер и брендинг:**
  - Использовать вымышленное название вуза (например, «Университет Цифровых Технологий — УЦТ») и уникальный минималистичный SVG-логотип.
  - В футере и на экране входа разместить заметную плашку: *«Концептуальный прототип для студенческого конкурса. Не является официальным сервисом вуза. Все персональные данные вымышлены»*.

## 2. Рекомендуемый стек
- **Frontend:** Next.js (App Router) + TypeScript + Tailwind CSS + Lucide Icons.
- **Backend & DB:** Next.js API Routes + SQLite + Prisma ORM — чтобы проект легко разворачивался одной командой без сложных внешних зависимостей.
- **Auth & Security:** JWT в `httpOnly` cookie, хэширование паролей через `bcryptjs`.

## 3. Безопасность и изоляция данных (Критично!)
1. **Защита от IDOR:** Любой API-запрос (`/api/grades`, `/api/requests`, `/api/schedule`) определяет пользователя исключительно из токена сессии на сервере. Передача `userId` в query-параметрах или теле запроса запрещена.
2. **Проверка прав:** Студент А не может просмотреть или изменить заявку Студента Б даже при прямом обращении к эндпоинту `/api/requests/[id]` (сервер возвращает `403 Forbidden`).
3. **Никаких секретов на клиенте:** Все ключи и соль для JWT хранятся только в `.env` (в репозиторий кладётся `.env.example`).

## 4. Функциональные разделы

### 4.1. Экран входа и Демо-режим Face ID
- Классическая форма: Логин + Пароль + кнопка «Войти».
- Кнопка **«Войти по Face ID (Демо-режим)»**:
  - Открывает модальное окно / шторку с выбором одного из 3 тестовых аккаунтов.
  - После клика проигрывается 1.5-секундная анимация сканирования лица (рамка с лучом → галочка «Личность подтверждена»).
  - Под капотом отправляется настоящий POST-запрос на `/api/auth/demo-login`, который создаёт реальную защищённую сессию для выбранного пользователя.
  - Подпись в модалке: *«Демонстрация концепции биометрического входа. В боевой версии реализуется через WebAuthn / Passkeys»*.

### 4.2. Главный экран («Сегодня») и Профиль
- Карточка студента: ФИО, факультет, направление, курс, номер группы, номер студбилета.
- Виджет **«Ближайшая пара»** (время, аудитория, преподаватель, статус).
- Виджет **«Пульс семестра»** (прогресс-бар допуска к сессии, количество сданных зачётов/КР).
- Быстрые действия: «Заказать справку», «Ближайшие дедлайны».

### 4.3. Расписание
- Переключатель режимов: **«Сегодня»** и **«Вся неделя»**.
- Карточка пары: время, название дисциплины, тип (лекция/практика), преподаватель, корпус и аудитория.
- **Выделение изменений:** Перенесённые или отменённые пары выделяются цветным бейджем (например, *«Перенос из ауд. 304 в 512»* или *«Занятие отменено»*).

### 4.4. Успеваемость и Экспорт в календарь (Авторская фича)
- Список дисциплин текущего семестра: текущие баллы, статус зачёта, дата экзамена или контрольной работы (КР).
- **Интеграция с личным календарём (`.ics`):**
  - Рядом с каждой КР, зачётом и экзаменом есть кнопка **«В календарь»**.
  - При клике открывается поповер с выбором напоминаний (чекбоксы: *за 3 дня*, *за 1 день*, *за 2 часа*, *без напоминаний*).
  - Клиентская утилита генерирует валидный `.ics` файл (стандарт iCalendar с тегами `VALARM`, `LOCATION`, `DESCRIPTION`) и инициирует его скачивание/открытие в системном календаре телефона или ПК.
  - Кнопка **«Экспортировать всю сессию (.ics)»** для выгрузки всех важных дат одним файлом.

### 4.5. Заявки и справки (+ Режим методиста)
- Список поданных заявок со статусами: `Принято`, `В обработке`, `Готово к выдаче`, `Отклонено`.
- Форма подачи новой заявки: выбор типа (*Справка об обучении*, *Справка для военкомата*, *Материальная помощь*, *Перевод на бюджет*), комментарий, мгновенное появление в списке.
- **Для роли «Сотрудник деканата»:** интерфейс просмотра всех заявок студентов с возможностью поменять статус заявки (после смены статуса у соответствующего студента появляется уведомление).

### 4.6. Уведомления
- Лента уведомлений с фильтром «Все / Непрочитанные» и счётчиком в меню:
  - Автоматические уведомления о смене статуса справки.
  - Предупреждения о переносе пар и приближающихся КР.
  - Объявления деканата.

- Продуманные **Empty States** (если уведомлений или долгов нет — дружелюбная иллюстрация/иконка и текст).

- Чёткая контрастность, крупные зоны нажатия для пальца (`min-height: 44px`).
